# تشغيل تطبيق الطبيب (dental_app) + إشعارات الحجوزات الجديدة

هذا الدليل يشرح الخطوات التي **لازم تنفّذها إنت بنفسك** (مش ممكن تلقائياً من هون)، عشان تطبيق الطبيب على أندرويد يشتغل ويستقبل إشعار فوري كل ما مريض يحجز موعد جديد من رابط الحجز العام `/d/<slug>`.

---

## 1) إنشاء مشروع Firebase (مجاني بالكامل)

1. افتح https://console.firebase.google.com وسجّل دخول بحساب Google.
2. "Add project" → اختار اسم (مثلاً `dental-clinic-faras`) → أكمل الخطوات (تقدر تعطّل Google Analytics، مش لازم).
3. داخل المشروع: اضغط أيقونة أندرويد "Add app" → أندرويد.
   - **Package name**: لازم يطابق بالضبط القيمة الموجودة حالياً في
     `dental_app/android/app/build.gradle.kts` عند `applicationId` — حالياً هي:
     ```
     com.example.dental_app
     ```
     (لو غيّرتها لاسم تاني قبل هيك، استخدم القيمة الجديدة بدل هاي).
   - اضغط "Register app"، ثم **نزّل ملف `google-services.json`**.
4. **حط الملف اللي نزّلته هنا بالضبط**:
   ```
   dental_project/dental_app/android/app/google-services.json
   ```
   ⚠️ بدون هالملف، أي محاولة بناء (`flutter build` أو `flutter run`) هتفشل فوراً بخطأ من Gradle — هذا متوقّع ومقصود.

---

## 2) توليد بيانات اعتماد السيرفر (Service Account) لإرسال الإشعارات

1. بنفس مشروع Firebase: ⚙️ Project settings → تبويب **Service accounts**.
2. اضغط "Generate new private key" → يتنزّل ملف JSON (احتفظ فيه، ما تشاركه مع حدا — هو مفتاح سري كامل الصلاحية لمشروعك).
3. افتح الملف بأي محرر نصوص، وانسخ **محتواه بالكامل كنص واحد** (كل الـ JSON من `{` لـ `}`).

---

## 3) ضبط متغيّرات البيئة على Render

روح لوحة تحكم Render → السيرفس بتاعت الـ backend → **Environment** → أضف متغيّرين جدد:

| المفتاح | القيمة |
|---|---|
| `FIREBASE_PROJECT_ID` | معرّف المشروع من Firebase (Project settings → General → **Project ID**، مش الاسم المعروض) |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | محتوى ملف الـ JSON اللي نسخته بالخطوة السابقة، كنص واحد كامل |

بعد ما تحفظ المتغيّرين، **اضغط Manual Deploy** (زي كل مرة — التذكير المعتاد: هاد المشروع ما بينشر تلقائياً عند كل push لـ GitHub).

> ملاحظة: لو نسيت تضبط هالمتغيّرين، التطبيق والموقع بيستمروا يشتغلوا طبيعي 100%، بس الإشعارات ما رح توصل — الكود مكتوب بحيث ما بوقف أي عملية حجز أبداً حتى لو فشل إرسال الإشعار.

---

## 4) بناء تطبيق الأندرويد محلياً على جهازك

من مجلد المشروع، بالـ Terminal:

```bash
cd dental_app
flutter pub get
```

لو ظهر خطأ تعارض إصدارات (version resolution)، جرّب:
```bash
flutter pub upgrade --major-versions
```

بعدين ابنِ ملف APK جاهز للتثبيت:
```bash
flutter build apk --release
```

الملف الناتج بيكون هون:
```
dental_app/build/app/outputs/flutter-apk/app-release.apk
```

انسخه لهاتف الأندرويد (عبر كيبل، بلوتوث، أو رفعه لجوجل درايف وتنزيله)، وفعّل "التثبيت من مصادر غير معروفة" لو طلب منك، وثبّته.

للتجربة السريعة أثناء التطوير (بدون بناء APK كامل كل مرة)، لو عندك هاتف موصول بالكيبل أو محاكي (emulator) شغّال:
```bash
flutter run
```

---

## 5) تسجيل الدخول واختبار الإشعار

1. افتح التطبيق، سجّل دخول بنفس بريد وكلمة سر أي طبيب عنده حساب على الموقع.
2. من جهاز/متصفح تاني (أو حتى من نفس الهاتف بمتصفح Chrome)، افتح رابط الحجز العام لهاد الطبيب: `https://dental-clinic-faras.onrender.com/d/<slug>` واعمل حجز تجريبي.
3. المفروض يوصل إشعار "📅 طلب حجز جديد" على هاتف الطبيب خلال ثوانٍ، والضغط عليه يفتح التطبيق مباشرة على تبويب "جدول اليوم".

---

## ملاحظات مهمة

- **التوزيع حالياً APK مباشر فقط** (مو من Google Play) — يعني كل تحديث مستقبلي للتطبيق لازم يتبني ويتوزّع يدوياً بنفس طريقة الخطوة 4، وما في تحديث تلقائي للطبيب.
- الـ `applicationId` لسا `com.example.dental_app` (قيمة افتراضية من القالب) — تمام للاستخدام الداخلي/الشخصي، بس لو بتفكر تنشر التطبيق على Google Play يوماً لازم تغيّرها لاسم فريد خاص فيك (مثلاً `com.faras.dentalapp`) **قبل** إنشاء تطبيق Firebase (لأنها لازم تتطابق).
- لو ظهر خطأ Gradle بخصوص `minSdkVersion` عند البناء (نادر لكن ممكن)، ارفع القيمة في `android/app/build.gradle.kts` من `flutter.minSdkVersion` إلى `23` يدوياً.
- كل الكود الخلفي (backend) الجديد إضافي بالكامل (additive) — ما تم حذف أو تعديل أي مسار قديم، فالموقع نفسه ما بيتأثر إطلاقاً.
